# Инструментальная архитектура через связи

## 1. Единица архитектуры

Инструмент рассматривается как узел с явно определёнными входами, действиями, выходами, состоянием и связями.

`INPUT → TOOL → OUTPUT`

Полный рабочий цикл:

`INPUT → ACTION → RESULT → VERIFY → STATE → NEXT`

## 2. Связь — первый класс

Связь не является скрытой ссылкой. Она должна иметь:

- `id` — идентичность;
- `source` — источник;
- `target` — назначение;
- `type` — смысл связи;
- `provenance` — происхождение;
- `state/history` — состояние и история при необходимости.

Форма:

`NODE → EDGE → NODE`

## 3. Инструментальная цепочка

Базовый пример:

`Editor → Terminal → Verify → Git → GitHub`

Каждый переход передаёт результат следующему узлу. Ни один узел не считается выполненным только по факту запуска.

## 4. Обратная связь

Результат проверки возвращается к узлу, который создал или изменил состояние:

`ACTION → RESULT → VERIFY → FEEDBACK → ACTION'

Если проверка не пройдена, состояние не продвигается в следующий уровень статуса.

## 5. Граница проекта и инструмента

Разрешённые связи:

`PROJECT → TOOL`

`TOOL → TOOL`

Запрещённые связи для публичного слоя:

`PUBLIC TOOL → PRIVATE PROJECT`

`PRIVATE PROJECT DATA → PUBLIC TOOL`

Инструмент должен оставаться переносимым после удаления конкретных проектных данных.

## 6. Память и происхождение

Каждое значимое состояние должно иметь происхождение:

`SOURCE → STATE → CHANGE → VERSION → RESULT`

Для переносимого инструмента дополнительно:

`SOURCE → EXTRACT → ISOLATE → SANITIZE → VERIFY → PORTABLE → PUBLISH`

## 7. Статус как состояние

Статус инструмента является частью его состояния:

`IDEA → DEVELOPMENT → WORKING → VERIFIED → STABLE`

Переход выполняется только при наличии соответствующего доказательства.

## 8. Контроль целостности

Архитектура считается согласованной, если:

- каждый узел имеет назначение;
- каждая критическая связь имеет источник и назначение;
- происхождение результата известно;
- проверка отделена от выполнения;
- обратная связь возвращается в систему;
- публичный инструмент не зависит от приватного проекта;
- состояние можно восстановить по истории.

## 9. Главный принцип

**Не хранить только элементы. Хранить элементы вместе со связями, состояниями, происхождением и обратной связью.**
