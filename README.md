# instrument-Open

Открытая база **самостоятельных инструментов** для построения, проверки, запуска и развития цифровых систем.

## Назначение

Здесь описываются сами инструменты, а не прикладные проекты, в которых они могут использоваться.

Инструмент может быть подключён к любому проекту без изменения своей собственной архитектуры.

## Архитектура

**разное → связь → целое → обратная связь → уточнение элементов**

Связь рассматривается как самостоятельный объект: `source → edge → target`.

Полный рабочий цикл:

**input → action → result → verify → state → next**

Подробная карта находится в [`ARCHITECTURE.md`](ARCHITECTURE.md), а таблица связей — в [`TOOLS/TOOL_RELATION_MAP.md`](TOOLS/TOOL_RELATION_MAP.md).

## Базовые инструменты

- **Git** — история и контроль состояний.
- **GitHub** — удалённое хранение и публикация.
- **Terminal** — выполнение и проверка операций.

## Подключение

Практическая инструкция находится в [`TOOLS/CONNECT.md`](TOOLS/CONNECT.md).

## Статусы

Инструменты проходят градацию:

**IDEA → DEVELOPMENT → WORKING → VERIFIED → STABLE**

Отдельно фиксируются `FAILED`, `BLOCKED` и `DEPRECATED`.

`WORKING` не означает `VERIFIED`: рабочий запуск и доказанная корректность — разные состояния.

## Guardian

Перед переносом инструмента в публичный слой применяется защитная цепочка:

**source → extract → isolate → sanitize → verify → portable → publish**

Инструмент переносится. Проект остаётся на месте.

## Обратная связь

Положительные и отрицательные результаты фиксируются вместе с версией инструмента, датой, проверенным сценарием и доказательством результата.

## Независимость

**Инструмент не принадлежит проекту. Проект использует инструмент.**

В публичную базу не включаются внутренние архитектуры, данные и зависимости конкретных прикладных проектов.
